Understanding Signals and Features

Separate measurements, scores, decisions, targets, orders, and actual holdings across a causal event timeline.

⏱ 75 min● Concept + calculation + practice⌁ H TO H assignment linked
Learning objectives

By the end, you can…

  • Distinguish feature, score, signal, target, order, and holding
  • Explain lagging at the signal-to-execution boundary
  • Design state transitions without accidental churn
  • Test a signal before embedding it in a portfolio

Intuition first

A forecast becomes money only after several transformations

A feature is a measured input: 63-day return, distance from a moving average, or volatility. A score combines evidence into a comparable number. A signal maps that number to a decision state. A target specifies desired exposure. An order requests a transition. Actual holdings appear only after a fill.

These layers should be inspectable. If a feature predicts next-period return but a threshold trades too often, the portfolio can lose after costs. Conversely, a signal can be directionally correct less than half the time yet profitable if winners are larger than losers. Classification accuracy is not strategy expectancy.

State matters. A hysteresis rule might enter above a high threshold and exit only below a lower threshold, reducing churn. But it introduces path dependence that must be implemented deterministically and tested on truncated history. Task 1 can recompute the whole position series; Task 2 offers a persistent state dictionary for cached, causal information.

Questions beginners actually ask

Clear answers before we add mathematics

Why separate a feature from a signal?

A feature is a measurement, such as a 63-day return. A signal interprets it; a target requests exposure; an order asks for execution. Separating the layers makes timing, turnover, and bugs visible.

Can a low-accuracy signal still make money?

Yes. Four large wins can outweigh six small losses. Profitability depends on the whole payoff distribution and costs, not only how often direction was correct.

Follow the mechanism slowly

What happens first, second, third, and fourth

01

Measure a feature

Turn historical data into a number such as return, distance, or volatility. The feature should have a clear timestamp.

02

Interpret evidence

A score or threshold converts measurements into a view. Changing a threshold changes exposure and turnover as well as selectivity.

03

Request a target or order

Task 1 outputs desired signed exposure; Task 2 outputs instructions conditional on current holdings. Neither is yet a guaranteed fill.

04

Account for actual holdings

The engine applies lag, price, constraints, and costs. Strategy profitability belongs to this final executed path, not the raw score alone.

Deeper explanation

Signal accuracy is not the same as decision value

A score can correlate weakly with later returns yet fail as a trading rule because thresholds discard information or concentrate trades at costly times. Conversely, a low hit-rate signal can work through large winners. Evaluate calibration, payoff by score bucket, turnover, and tail behavior before choosing a final state mapping.

Testing the feature separately helps locate failure. If higher scores do not produce stronger subsequent outcomes, portfolio construction cannot create genuine information. If the relationship exists gross but vanishes after fills and costs, the problem is implementation economics rather than feature calculation.

State transitions deserve their own specification

A rule that says “long when score is positive” flips every time the score crosses zero. Small noisy movements can create high turnover. Hysteresis might enter above +a and exit below +b, but then yesterday’s state affects today’s decision.

Write a transition table for every prior state and current condition. Test sequences such as flat→long→long→flat and long→short. This prevents accidental gaps, double entries, or dependence on mutable state that cannot be reproduced from the history.

Worked walkthrough

Accuracy versus expectancy

Ten trades: four winners of +5% and six losers of −2%. Win rate = 40%. Average trade = (4×5%−6×2%)/10 = +0.8% before costs. Now suppose 0.5% round-trip cost: average falls to +0.3%. Accuracy alone would reject a potentially positive payoff profile; costs show how thin the remaining edge is.

Implementation lens

Explicit transformation

feature = close / close.shift(63) - 1
score = feature / rolling_vol.replace(0, np.nan)
target = pd.Series(0, index=close.index)
target[score > threshold] = 1
# harness, not this code, applies target at next open

Assignment connection

Why this matters for my H TO H Partners assignment

Task 1 expects target positions directly. Task 2 expects orders informed by current holdings and cash. In a walkthrough, naming the layer you are modifying prevents vague explanations and off-by-one fixes in the wrong place.

Failure prevention

Common mistakes

  • Calling a feature a position
  • Comparing signal accuracy without payoff size
  • Letting a target earn pre-fill returns
  • Using persistent state to hide future or full-sample calculations
