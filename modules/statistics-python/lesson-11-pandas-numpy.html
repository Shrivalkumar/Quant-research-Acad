Intuition first

Correct alignment matters more than clever syntax

A pandas Series pairs values with an index; a DataFrame aligns rows and columns by labels. Task 1 uses a DatetimeIndex and OHLC columns. Task 2 converts long stock rows into wide date × symbol matrices. Alignment is powerful but can silently produce NaNs or mismatched arithmetic when labels differ.

shift(1) moves values down one row, expressing “previous observation.” rolling(L) creates trailing windows. pct_change(L) computes a fractional change relative to L rows earlier. In long format, every lag and rolling calculation must be grouped by symbol; otherwise the last row of one stock can become the “previous” row of another.

Cross-sectional rank is along columns for each date (axis=1). Time shift is along rows. Resampling needs an OHLC aggregation map and careful treatment of incomplete intervals. Vectorization is usually faster than Python loops, but Task 2’s growing hist means recalculating 790×555 full histories daily can still be wasteful; slice the needed tail or cache deterministic state.

Questions beginners actually ask

Clear answers before we add mathematics

Why does pandas alignment matter?

Pandas matches labels, not just physical positions. Two objects with different dates or symbols can produce missing values or unexpected pairings. Inspect indexes and columns before trusting a calculation.

What is cross-stock leakage?

It occurs when information from one company’s history accidentally enters another company’s feature—for example, using an ungrouped lag in long-form data. Every symbol’s time operations must stay inside that symbol.

Follow the mechanism slowly

What happens first, second, third, and fourth

01

Inspect shape and labels

Print index type, date order, columns, dtypes, and sample rows. A correct formula on the wrong axis is still wrong.

02

Transform within the right group

Long-form stock lags require grouping by symbol. Wide-form time operations run down rows, while cross-sectional ranks run across columns.

03

Handle NaNs explicitly

Specify minimum observations and avoid implicit filling. Missing values can represent listing history, unavailable quotes, or an undefined calculation.

04

Verify on labeled toy data

Use two symbols and a handful of dates to inspect every shifted denominator and rank. Only then scale vectorized code to the full pack.

Deeper explanation

Think in tables before thinking in methods

For Task 2, visualize one wide close table: rows are dates, columns are symbols, cells are closing prices or NaN. A time-series operation travels downward within a column. A cross-sectional rank travels horizontally across one row. Most axis mistakes become obvious from this picture.

Long format stores date, symbol, and value in rows. It is compact and flexible, but lagging must occur inside each symbol group. Converting between long and wide layouts can introduce duplicates or memory costs; audit the uniqueness of date-symbol pairs before pivoting.

Vectorization improves speed but can hide logic

A vectorized expression computes many dates at once, which is fast and concise. It can also make a wrong shift propagate silently across the entire sample. Use explicit intermediate names—denominator, feature, eligibility, rank—and inspect a few labeled rows.

Task 2 calls the strategy once per date with a growing history. Recomputing every feature over all 790 dates and 555 symbols on every call repeats work. Slice the longest necessary trailing window or cache only causal results in state, then verify that the optimization does not change outputs.

Worked walkthrough

Preventing symbol bleed

Long rows: A on Monday and Tuesday, then B on Monday and Tuesday. Plain df.close.pct_change() computes B Monday relative to A Tuesday—a nonsensical cross-stock return. Correct: sort by symbol/date and use df.groupby("symbol").close.pct_change(fill_method=None). After pivoting, each column naturally isolates a symbol for row-wise time operations.

Implementation lens

Core research workflow

long = long.sort_values(['symbol', 'date'])
long['ret1'] = (long.groupby('symbol')['close']
                    .pct_change(fill_method=None))
wide = long.pivot(index='date', columns='symbol', values='close')
mom = wide / wide.shift(63) - 1
rank = mom.rank(axis=1, ascending=False, method='first')

Educational pattern—adapt only after you can explain every line.

Failure prevention

Common mistakes

  • Shifting columns when intending time
  • Rolling long data without grouping
  • Relying on deprecated implicit fill in pct_change
  • Using rank default axis incorrectly
  • Recomputing the full history every day without need

  1. axis=0
  2. axis=1
  3. groupby symbol only
  4. resample
Reveal explanation

Answer: B. Each row compares symbols across columns.

2. Why group long-format returns by symbol?

  1. To change currency
  2. To stop one symbol’s row becoming another’s lag
  3. To fill NaNs
  4. To add leverage
Reveal explanation

Answer: B. Lags must stay inside each asset history.

  1. Percentage points already ×100
  2. Fractional change
  3. Log return
