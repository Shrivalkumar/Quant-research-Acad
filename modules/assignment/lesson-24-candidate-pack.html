Intuition first

The harness is executable law for this assignment

The pack contains nine files: README, public harness, two templates, four CSV/text data assets, and symbols.txt. Task 1 has 29,803 15-minute spot bars from 3 Apr 2017 to 31 Jan 2022 and 61 expiry dates. Task 2 has 400,949 rows across exactly 555 stocks and 790 trading dates, ending 28 Jun 2024.

positions(bars, params) must return one −1/0/+1 per Task 1 bar. The harness shifts targets one bar, forces actual positions flat for the first 200 bars, and samples four truncated histories for a look-ahead check. orders(date,hist,portfolio,params,state) receives only history through the close and returns one-day next-session orders.

Task 1 daily contributions include prior-position gap return, current-position intrabar return, cost on absolute position change, overnight signed carry, expiry roll, and daily cash. Task 2 executes market sells, buys, then stop sells; caps new weights at 15%, holdings at 15, forbids adding/shorting, and charges 0.2% per side.

Questions beginners actually ask

Clear answers before we add mathematics

Which document wins when instructions seem inconsistent?

For scoring behavior, the supplied harness is executable authority and the README explains its intended interface. The assignment email supplies objectives and report requirements. Do not substitute generic backtester assumptions.

Does passing the harness look-ahead check prove my code is safe?

No. It checks four sampled Task 1 truncation points. It is useful, but your own feature-level timing tests and Task 2 audits are still required.

Follow the mechanism slowly

What happens first, second, third, and fourth

01

Load the module and validate parameters

The harness imports the submitted file, requires a PARAMS dictionary, and enforces the six-entry maximum.

02

Load and shape supplied data

Task 1 becomes a sorted DatetimeIndex; Task 2 becomes wide date-by-symbol frames with Nifty aligned to stock dates.

03

Call the strategy under its interface

Task 1 calls positions over bars and performs sampled truncation checks. Task 2 calls orders after each close with persistent state.

04

Run accounting and statistics

The harness owns fills, costs, cash, positions, equity, trades, and metrics. Your code should not bypass this boundary by reading data files itself.

Deeper explanation

Task 1 accounting, narrated bar by bar

At bar i open, the position selected after bar i−1 close becomes active. The old overnight position earns the gap from prior close to this open. The new actual position earns the current open-to-close move. Any change between old and new positions pays cost.

On the first bar of a new day, the overnight position also receives or pays modeled carry and may pay roll if the previous date is an expiry. Bar contributions are summed within each date, then daily cash is added and equity compounds. This narration should match every array in task1_backtest.

Task 2 accounting, narrated day by day

After close t, orders() sees close-valued equity and history through t. On t+1, market sells execute first, then buys in listed order, then qualifying stop sells. Buy amount is based on prior close equity but capped by cash; shares depend on actual fill and the buy-side cost.

At the close, all open holdings are valued using the latest available close. The engine records equity and calls the strategy again. Unfilled orders vanish. Open terminal positions remain in equity but are absent from closed-trade statistics.

Worked walkthrough

Three pack facts worth testing

Short session: 1,192 days have 25 bars; 4 Nov 2021 has 3. Short source bars: one bar contains 13 one-minute candles and two contain 14. Listing history: symbols range from 3 to 790 observations. Any rule assuming equal histories is wrong.

The template runs measured 11.65% CAGR / 0.536 Sharpe for Task 1 and 53.06% / 1.638 for Task 2 on the supplied pack. These are sanity baselines, not target designs.

Failure prevention

Common mistakes

  • Believing the brief’s approximate 585 count over the actual 555
  • Assuming 30 Jun 2024 is an observed trading date
  • Using current live expiry rules instead of supplied expiries
  • Claiming the four-point look-ahead check proves all causality
